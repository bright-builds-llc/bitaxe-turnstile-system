# Repository Ownership

Repositories are created only when implementation work begins. This map assigns responsibility without requiring empty scaffolds during design.

| Repository                 | Owns                                                                                                                                                                                                                                                                 | Explicitly does not own                                                                                        |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| `bitaxe-turnstile-system`  | Gate specifications; OpenAPI, Protobuf, Worker Controller, and local transport profiles; Rust Gate Authority and domain crates; Pool Adapter SDKs and implementations; browser adapters; SolidJS gate widget; operator console; conformance fixtures; reference demo | Device fleet control; firmware; Mining Pool engine internals                                                   |
| `bitaxe-esp-miner-c`       | Reference Firmware; application USB function implementation; USB provisioning and control; Work Lease execution; Mining Baseline restoration; Device Identity; outbound Device Relay client; native hardware evidence                                                | Gate Policy; transport-profile authorship; Credited Work accounting; Gate Pass issuance; website authorization |
| `bitaxe-worker-management` | Device Relay; Identity and Access; Control Grants; pairing backend; SolidJS web management; Capacitor mobile shell and narrow native bridges; shared management packages                                                                                             | Mining Pool accounting; Gate Policy; firmware implementation                                                   |
| External pool repositories | Bitcoin job construction; Stratum services; accepted shares; candidate blocks; rewards                                                                                                                                                                               | Protected Actions; Gate Passes; Account Identities; device management                                          |

Cross-repository contracts are published as versioned crates or packages and exercised through shared conformance fixtures. External pool licenses remain disclosed and isolated by Pool Adapter process boundaries.

Reference Firmware moved from the Rust `bitaxe-esp-miner` repository to `bitaxe-esp-miner-c`, a GPL-3.0 fork of upstream ESP-Miner, on 2026-10-30 ([ADR-0105](../adr/0105-reference-firmware-is-the-c-fork-of-esp-miner.md)). The Rust repository and its evidence remain historical records.

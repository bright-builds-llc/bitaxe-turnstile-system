# BWG Worker Possession 0.1

## Scope

`bwg-worker-possession/0.1` proves that a newly admitted Worker USB 0.2 enumeration controls the
same Reference Firmware Device Identity. It is a local pre-admission profile, not a Pairing
Ceremony, Control Grant, account identity, remote relay, or hardware-attestation claim.

## Request and proof

The browser sends one bounded `prove_possession` request containing a unique `pos_*` request ID and
five exact bindings:

- `purpose`: `initial_admission` or `transport_reacquisition`;
- `possessionNonce`: 32 fresh browser-generated bytes encoded as base64url;
- `challengeBindingSha256`: a local digest binding this proof to one Work Challenge;
- `controllerCapabilitySha256`: the canonical signed Controller 0.3 capability digest; and
- `applicationDescriptorSha256`: the exact Worker USB application descriptor digest.

Reference Firmware returns the correlated bindings, its public Ed25519 Device Identity JWK, and a
compact JWS with protected type `bwg-worker-possession+jws`. It signs only this closed canonical
claim shape. Arbitrary messages, Work Lease credentials, unknown fields, weak keys, and oversized
or multiple frames are invalid.

Initial admission verifies the JWS and establishes the SHA-256 fingerprint of the canonical public
JWK. Reacquisition uses a fresh nonce and requires that exact fingerprint. A proof is single-use in
the client even when verification fails or runs concurrently.

## Privacy and non-claims

Live proofs, JWKs, fingerprints, raw USB identity, credentials, and challenge identifiers never
enter logs, evidence, telemetry, public state, or backend requests. Published conformance fixtures
use one explicitly marked non-production identity and contain no private seed. Possession proves
continuity only while the private key remains secret; it is not tamper-proof hardware identity.

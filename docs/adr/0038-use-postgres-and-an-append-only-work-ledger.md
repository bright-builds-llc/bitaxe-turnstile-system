# Use PostgreSQL and an append-only work ledger

PostgreSQL will authoritatively store immutable challenge issuance policy, Work Sessions, deduplicated append-only Accepted Work Events, cumulative Credited Work projections, Gate Pass metadata, expiry state, and adapter acknowledgements. One transaction inserts each new event, computes exact work, advances completion, and records downstream issuance intent; caches and SSE fan-out remain disposable, avoiding full event-sourcing complexity without losing auditability or reconstruction. Runnable services and durability acceptance paths use PostgreSQL, while in-memory repositories are limited to isolated domain-unit tests.
